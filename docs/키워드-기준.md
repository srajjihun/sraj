# 키워드 선정·검증 기준

우리가 나라장터 공고를 "우리 일"과 "우리 일이 아닌 것"으로 나누는 규칙과,
그 규칙을 고칠 때 무엇을 근거로 판단하는지를 적은 문서입니다.

- 규칙이 실제로 적혀 있는 곳: `config/g2b-keywords.md` (이 파일 하나만 고치면 됩니다)
- 규칙을 해석하는 코드: `scripts/g2b/lib/keywords.mjs`
- 규칙을 시험하는 도구: `단어확인.bat` · `키워드-검증.bat`

작성 기준일: 2026-08-19 · 현재 설정 = 6개 분야 · 수집어 77개 · 제외어 220개

---

## 1. 큰 그림 — 공고 한 건이 화면에 뜨기까지

```
나라장터 API
   │  ① 받아올 범위    용역만 · 참가제한지역 전국(00)+서울(11)
   ▼
data/g2b/raw/         ← 키워드와 무관하게 원본 그대로 전부 보관
   │  ② 판정          아래 2장의 다섯 가지 규칙
   ▼
data/g2b/posts.json   ← 우리 일이라고 판정된 것만
   │  ③ 정리          마감 지난 것 제외
   ▼
g2b-live.html
```

**원본을 통째로 보관하는 것이 이 설계의 핵심입니다.** 키워드를 고쳐도 다시
수집할 필요가 없습니다. `화면-새로고침.bat` 한 번이면 이미 받아둔 과거 공고
전부에 새 규칙이 소급 적용됩니다(`reclassify.mjs`). 그래서 규칙을 과감하게
고쳐 보고 결과를 본 뒤 되돌릴 수 있습니다 — 이 문서의 모든 판단은 그 위에
서 있습니다.

API 단계에서 이미 **물품·공사는 받지 않습니다**. 우리는 용역만 합니다.
그래서 키워드는 "용역 안에서 우리 분야를 고르는" 일만 하면 됩니다.

---

## 2. 판정 규칙 다섯 가지

`config/g2b-keywords.md` 는 다섯 개의 목록으로 되어 있고, 공고 하나는 이
순서대로 통과해야 화면에 뜹니다.

| 순서 | 목록 | 하는 일 | 개수 |
|---|---|---|---|
| ① | `# 수집 키워드` | 공고명에 이 단어가 있으면 후보 | 77 |
| ② | `# 수집 예외` | 그런데 이 말 **안에서만** 걸렸으면 무효 | 5 |
| ③ | `# 제외 키워드` | 후보라도 이 단어가 있으면 버림 | 220 |
| ④ | `# 제외 예외` | 그런데 이 말 **안에서만** 걸렸으면 안 버림 | 43 |
| ⑤ | `# 제외 해제` | 왼쪽 말이 제목에 있으면 오른쪽 제외어는 무시 | 15줄 |

### ① 수집 키워드 — 부분문자열로 걸립니다

`창업` 한 줄이면 예비창업·초기창업·창업보육·창업중심대학·재창업이 전부
걸립니다. 그래서 파생어를 일일이 적지 않습니다. 반대로 **짧은 단어일수록
엉뚱한 말 속에 박혀 있을 위험**이 커집니다. 새 단어를 넣기 전에 반드시
`단어확인.bat` 으로 실제 건수를 봅니다(3장).

여섯 분야와 개수:

| 분야 | 수집어 | 대표 단어 |
|---|---|---|
| 창업지원 | 13 | 창업 · 스타트업 · 액셀러 · 데모데이 · 펀딩 |
| 커머스 | 8 | 커머스 · 쇼핑몰 · 판로 · 입점 · 상세페이지 |
| 수출·해외진출 | 5 | 수출 · 진출 · 해외시장 · 바이어 · 무역 |
| 행사·교육 | 28 | 행사 · 축제 · 박람회 · 세미나 · 창업교육 |
| 마케팅·홍보 | 14 | 홍보 · 마케팅 · 공모전 · 캠페인 · 브랜딩 |
| 소상공인 | 9 | 소상공인 · 상권 · 전통시장 · 자영업 |

**분야를 적은 순서가 곧 우선순위입니다.** 한 공고가 여러 분야에 걸리면 위에
적힌 분야로 분류됩니다. "수출마케팅 협력사업(무역사절단)"은 수출과 마케팅에
둘 다 걸리는데, 수출·해외진출이 위에 있으므로 수출로 분류됩니다. 순서를
바꾸면 분류가 바뀝니다.

### ② 수집 예외 — 짧은 수집어가 남의 말 속에 박힌 경우

`무역`은 **직무역량**(직-무역-량) 안에도 들어 있습니다. 이것 때문에 HRD
교육 공고가 전부 수출 분야로 분류됐습니다. `무역량`을 수집 예외에 적어두면
그 안에서만 걸린 `무역`은 무시되고, "무역사절단 파견" 같은 진짜 무역 공고는
그대로 잡힙니다.

현재 등록: 무역량 · 해상무역 · 수출입은행 · 어드벤처 · 진출입

### ③ 제외 키워드 — 220개, 10개 묶음

목록이 큰 이유는 "우리 일이 아닌 것"이 "우리 일"보다 훨씬 다양하기
때문입니다. 묶음마다 무엇을 막는지 제목이 붙어 있습니다.

건설·설비 / 학교·아동 교육 / 시험·분석·검사 / 조사·연구·자문 /
영상·제작물 / 디자인·제작 / 인쇄·제작물 / 전시·공간 연출 / IT·보안 /
일반 관리·구매

**가장 중요한 판단 두 가지가 여기 들어 있습니다.**

- **"제작"을 통째로 막습니다.** 우리는 사업을 운영·대행하는 쪽이고 만들어
  내는 일은 하지 않습니다. 이 한 줄이 달력·자료집·애니메이션·화보집·
  브로슈어 제작을 한꺼번에 막습니다. 화면에서 빼달라고 지목된 오탐 25건의
  단어 빈도를 세어 보니 "제작"이 12건으로 압도적이었고, 유지 대상 30건에는
  1건뿐이었습니다.
- **"영상"을 통째로 막습니다.** 영상 대행을 다시 하기로 하면 제외어의
  `영상` 한 줄만 지우면 되돌아옵니다. 방송·송출·후반작업·VFX 도 이 줄에
  흡수됩니다.

### ④ 제외 예외 — 기관 이름 때문에 멀쩡한 공고가 죽는 것을 막습니다

`공사`는 건설공사를 막으려는 말인데 대한무역투자진흥공사·한국관광공사·
한국도로공사 이름에도 들어 있어 그 기관 공고가 통째로 사라졌습니다.
`진흥공사`를 예외에 적으면 기관명 안의 `공사`는 넘어가고 "청사 리모델링
공사"는 그대로 막힙니다. 같은 이유로 연구원·연구소(→`연구`),
정보통신·방송통신(→`통신공사`)도 등록돼 있습니다.

### ⑤ 제외 해제 — 맥락이 있으면 푼다

같은 단어라도 무슨 사업 안에 있느냐에 따라 뜻이 달라집니다.

| 조건어 | 풀리는 제외어 | 왜 |
|---|---|---|
| 수출 · 무역 · 바이어 · 진출 | 행사 전시회 전시 박람회 상담회 설명회 | 수출지원사업의 표준 형태가 "해외 전시회 참가지원"·"수출상담회"·"무역사절단 파견"입니다. 국내 행사 기획과는 다른 일입니다 |
| 창업 · 스타트업 · 대학 | 학년도 | 대학 창업지원단은 "2025학년도 …"로 발주합니다. 학년도 제외는 초중고를 막으려는 것입니다 |
| 상세페이지 · 입점 · 쇼핑몰 · 온라인몰 | 제작 제작물 | 커머스 입점 지원은 "상세페이지 제작 지원"이 표준입니다. 우리가 만드는 게 아니라 입점기업이 만들도록 지원하는 사업입니다 |
| 창업 · 스타트업 · 시제품 · 사업화 | 제작 제작물 | "로컬창업 아이디어 구체화 시제품 제작"처럼 참여기업이 만들고 우리는 운영을 대행합니다 |

## 3. 공고명만 봅니다 — 조달분류명은 쓰지 않습니다

한때 조달분류명(예: "광고및홍보서비스")도 같이 봤습니다. **이것이 오탐의
최대 원인이었습니다.** 화면에서 빼달라고 지목된 25건 중 13건은 공고명에
우리 키워드가 한 글자도 없었고, 전부 분류명에 걸린 것이었습니다. 조달분류는
업종 코드라서 달력·자료집·애니메이션·브로슈어 제작이 전부 같은 칸에
들어갑니다.

그래서 2026-08-18부터 **공고명(`item.title`)만** 봅니다
(`keywords.mjs`의 `matchGroups`).

분류를 아예 안 쓰는 것은 아닙니다. `# 조달분류코드` 에 **정확한 코드**를
적으면 그 코드는 키워드 없이도 수집합니다. 분류"명" 문자열 매칭은 끄고,
확인된 코드만 화이트리스트로 쓰는 방식입니다. 지금은 0개 — `키워드-검증.bat`
의 후보 목록(4장)에서 적중률 높은 코드가 나오면 그때 넣습니다.

## 4. 검증 도구 — 추측 대신 숫자로

두 도구 모두 **PC에 저장된 원본에만 돌립니다.** 나라장터 API를 부르지 않으니
하루 호출 한도와 무관하고, 수집 데이터도 화면도 바꾸지 않습니다. 몇 초면
끝나므로 얼마든지 반복해도 됩니다.

### 단어확인.bat — "이 단어 하나를 넣을까 말까"

`node scripts\g2b\word-check.mjs 판촉 광고 유통` 처럼 단어를 나열합니다.
그 단어가 나온 공고를 셋으로 쪼개 보여줍니다.

```
· 제외어에 걸려 버려짐   : 넣어도 어차피 버려지는 것
· 다른 키워드가 이미 잡음 : 추가해도 새로 늘지 않는 것
· 이 단어라야 잡힘       : 실제 증가분  ← 이것만 보면 됩니다
```

이미 설정에 든 단어를 검사하면 **자기 자신은 빼고** 계산합니다. 그래야
"이 단어를 빼면 무엇을 잃는가"에 답이 됩니다. 실제 증가분에 딸린 공고
제목이 최대 12건 같이 나오므로, 그것이 우리 일이 맞는지 눈으로 봅니다.

### 키워드-검증.bat — 설정 전체를 한 번에 점검

원본 전체에 지금 설정을 돌려 다섯 가지를 보여줍니다.

1. **분야별 수집 예상 건수 + 제목 샘플** — 어느 단어에 걸렸는지 대괄호로 표시
2. **키워드별 건수** — 0건이면 뺄 단어, 유독 큰 단어는 오탐을 의심
3. **제외어가 걸러낸 것** — 아깝게 죽은 공고가 있는지
4. **아무 키워드에도 안 걸린 것** — 놓친 시장이 있는지
5. **발굴 후보 · 분류코드 후보** — 아래 기준으로 자동 추천

발굴은 단순 빈도가 아니라 **특이도**로 합니다.

```
특이도 = (그 단어가 나온 우리 분야 공고 수) ÷ (그 단어가 나온 전체 공고 수)
```

단순 빈도로 뽑으면 "운영·지원·사업" 같은 일반어만 나옵니다. 특이도가 높다는
것은 "그 단어가 나오면 대체로 우리 분야"라는 뜻이라 좋은 후보입니다.
자동 추천이 쓰는 문턱값:

| 목록 | 문턱 |
|---|---|
| 분야별 발굴 후보 | 최소 건수 이상 · 특이도 40% 이상 · 분야마다 상위 12개 |
| 미수집 공고 빈출어 | 최소 건수의 2배 이상 · 특이도 70% 이상 · 상위 20개 |
| 조달분류코드 후보 | 그 코드 5건 이상 · 새로 얻는 것 3건 이상 · 적중률 50% 이상 |

최소 건수는 `max(3, 전체 ÷ 2000)` 으로, 데이터가 커지면 기준도 같이
올라갑니다.

## 5. 넣고 빼는 기준

도구가 답을 정해주지는 않습니다. 도구는 숫자를 주고, 판단은 아래 기준으로
합니다.

**넣지 않는다**
- 실제 증가분 0건 — 넣을 이유가 없습니다. 실측으로 0건이던 9개를
  뺐습니다(공모대전·스마트스토어·플리마켓·백년가게 등). 그중 다섯은
  "이런 표기가 있을 것"이라 짐작해 넣은 복합어였는데 10만건에 한 건도
  없었습니다. **짐작으로 넣지 않습니다.**
- 증가분은 있으나 우리 일이 아님 — 제목 12건을 보면 대개 바로 압니다.
- 물량이 압도적인 단어 — `시제품`이 제조업 물품 사전규격 92건을 끌어와
  크라우드펀딩 분야를 통째로 오염시켰습니다. `상품`을 넣지 않은 것도 같은
  이유입니다(사전규격 8.9만건이 물품).

**뺀다**
- 다른 말 속에 박혀 오분류를 만드는 단어. `셀러`는 **액셀러**레이팅 안에
  들어 있어 창업지원 물량을 전부 커머스로도 분류하고 있었습니다. `통상`은
  "통상적 업무"에 걸립니다.
  → 단어 자체를 빼거나, 살려야 하면 `# 수집 예외`로 막습니다.
- 고객이 우리 고객이 아닌 단어. `직무교육`·`실무교육`은 표본 8건이 전부
  의료AI·스마트축산·학교운동부지도자였습니다.

**좁힌다 (통째로 막지 않고 복합어로)**
- `보험` → 보험가입·보험료·단체보험·배상책임. 보험 계약 조달을 막으려던
  말인데 "농업정책보험 홍보 용역"까지 죽였습니다.
- `여행` → 교육여행·수학여행. "경기 로컬여행 자원 발굴 및 홍보마케팅"이
  죽고 있었습니다.

**분류만을 위해 남긴다**
- `창업교육`·`취창업`은 다른 분야(창업지원)가 이미 잡으므로 수집 건수는
  안 변합니다. 그래도 남깁니다 — 빼면 그 공고가 행사·교육 탭에서 사라져
  분야가 없어집니다.

**한 줄로 되돌릴 수 있게 남긴다**
- HRD를 사업분야로 삼기로 하면 `직무교육` 한 줄만 되돌리면 됩니다.
- 영상 대행을 다시 하기로 하면 제외어의 `영상` 한 줄만 지우면 됩니다.
- "소상공인 디자인 지원사업 운영 대행"처럼 우리가 운영만 맡는 공고가 실제로
  보이면 `# 제외 해제`에 `지원사업 → 디자인` 한 줄이면 됩니다.

## 6. 고치는 순서

1. `config/g2b-keywords.md` 를 고칩니다 (저장소 쪽을 고쳐야 합니다 — PC에서
   고치면 다음 코드 받기에서 되돌아갑니다).
2. `키워드-검증.bat` 으로 전체 영향을 봅니다. 단어 하나만 볼 때는
   `단어확인.bat`.
3. `화면-새로고침.bat` — 이미 받아둔 원본에 새 규칙이 소급 적용됩니다.
   **재수집은 필요 없습니다.**
4. 화면에서 눈으로 확인합니다. 이 단계에서 걸러낸 오탐 25건이 2026-08-18
   개정(조달분류명 매칭 중단 + "제작" 제외)의 근거가 됐습니다.

### 파일에 규칙을 적을 때 지킬 것

- `## 그룹명` 아래에 **한 줄에 단어 하나**.
- 설명은 자유롭게 써도 됩니다 — 해석기가 문장형 줄(마침표로 끝나거나
  "합니다/됩니다"가 있거나 `예:` 로 시작하거나 20자를 넘는 줄)은 건너뜁니다.
  이 방어는 `selftest.mjs` 가 매번 확인합니다. 실제로 안내문 4줄이 조용히
  키워드 목록에 섞여 있던 적이 있습니다.
- `# 제외 해제`만 `조건어 → 제외어 제외어` 형식입니다.

## 7. 같은 잣대를 우리 실적에도 씁니다

`config/실적DB.md` 의 우리 실적 177건도 **똑같은 키워드 엔진**으로 분야를
매깁니다(`lib/records.mjs`). 실적 파일에는 분야를 저장하지 않고 읽을 때마다
다시 매깁니다.

잣대가 같아야 "이 공고 분야에 우리 실적이 몇 건"이라는 말이 뜻을 가집니다.
키워드를 고치면 공고 분류와 실적 분류가 **동시에** 바뀌므로 둘이 어긋날 일이
없습니다.
